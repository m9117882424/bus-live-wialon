# Бронирование автобусов

Отдельный сервис записи на автобус: расписание, бронирование в одну или две стороны, справочник остановок, белый список, история и подтверждение с QR-кодом. Интерфейс доступен на русском и турецком языках.

Подтверждения формируются для поездок. Пароли, ключ шифрования, базу и резервные копии необходимо хранить в закрытом доступе; для админки требуется HTTPS и защита от перебора.

## Запуск

Проверено на Python 3.10 и системный шрифт DejaVu Sans.

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt

# Задайте значения в окружении или закрытом файле конфигурации сервиса.
export BUS_ADMIN_PASSWORD='сильный-случайный-пароль'
export BUS_FERNET_KEY="$(python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())')"
export BUS_DB="$PWD/bus-booking.sqlite"
# Внешний HTTPS-адрес сервиса без завершающего слеша:
export BUS_PUBLIC_URL='https://bus.example.org'
python -m uvicorn app:app --host 127.0.0.1 --port 18345
```

Пассажирская страница — `/bus/`, админка — `/bus/admin`. Логин администратора — `admin`; пароль задаётся через `BUS_ADMIN_PASSWORD`. Для внешнего доступа обязателен HTTPS-прокси, а доступ к админке следует ограничить и защитить от перебора. Не помещайте реальные пароли, ключи, номера пропусков и базу данных в Git.

Ключ `BUS_FERNET_KEY` сохраняйте между перезапусками и резервируйте отдельно: при его замене ранее выданные QR-коды перестанут проверяться.

При первом запуске белый список пуст. Его можно заполнить в админке или задать переменную `BUS_INITIAL_CARDS` через запятую для **новой** базы; последующие запуски список не перезаписывают. Новая база создаётся со справочником остановок «Камп» и «Магазин».

## Работа

- Отправление и назначение выбираются из справочника. Остановку можно добавить, изменить или отключить. Переименование не переписывает историю поездок.
- Одна бронь может включать рейсы в обе стороны; места резервируются атомарно, а обратный рейс должен следовать между теми же остановками.
- Пассажир отменяет бронь по ссылке подтверждения, диспетчер — во вкладке «Бронирования». Отменяются все рейсы, которые ещё не отправились; уже начавшиеся рейсы сохраняются в истории. Места освобождаются сразу, а отменённые рейсы отмечаются в истории.
- После отмены проверка QR-кода отклоняет его. Ранее скачанные PDF и JPG остаются у пассажира без изменений, поэтому действительность подтверждения проверяется по QR-коду.
- Рейс можно удалить из расписания, если на нём нет предстоящих бронирований. История и действующие подтверждения прошедших поездок сохраняются.
- Белый список принимает `.xlsx` до 5 МБ с выбором листа и столбца. Предпросмотр показывает повторы и ошибки. Импорт может дополнять список или заменять его.
- Ссылка действует до 30 минут после последнего отправления; история сохраняется шесть месяцев. QR содержит подписанную ссылку на страницу подтверждения; пожелание видно пассажиру и диспетчеру на русском и турецком языках. Ранее выданные зашифрованные QR-коды остаются доступны для проверки администратором.
- PDF и JPG создаются в вертикальном формате 9:16. При изменении комментария уже скачанный файл нужно скачать повторно.
