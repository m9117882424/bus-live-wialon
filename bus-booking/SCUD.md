# Факт пассажиров по СКУД

Загрузка находится в админке, во вкладке «Разрешённые пропуска», отдельным блоком «Импорт отметок СКУД». Существующий импорт белого списка работает отдельно. Можно выбрать несколько XLSX; каждый файл до 6 МБ импортируется своей транзакцией. Лимит соответствует действующему proxy, менять Nginx не нужно. Разбор выполняется в рабочем потоке; исходный запрос читается с ограничением размера, без multipart/spool-файлов.

Поддержан формат BUS_SERVICE_ALL: Kart No — номер карты, Tarih — дата и время, Okuyucu Ad — название считывателя с госномером. Госномер извлекается и нормализуется, название считывателя не сохраняется. Также принимаются три безопасных столбца «Автобус», «Номер карты», «Время отметки». Несколько листов и расположение заголовка в первых 12 строках распознаются автоматически. Есть ограничения размера ZIP, количества листов, строк и столбцов. Формулы в трёх рабочих столбцах не принимаются.

Импорт использует только разрешённые столбцы: автобус, карта, время. ФИО, Sicil No/кимлик, паспорт, организация, направления считывателя и остальные столбцы не копируются в БД, ответы или журналы. Исходный Excel и его имя не сохраняются. Номер карты сохраняется строкой, включая явные ведущие нули. Дата без времени не угадывается. Время без часового пояса считается временем Турции; явный пояс приводится к Europe/Istanbul.

Хранение: scud_events(plate, card, stamp), где stamp — Unix milliseconds, ключ (plate,card,stamp). scud_days содержит дату загруженных данных и время импорта; scud_imports — только даты и числовые итоги обработки, без имён файлов или исходных строк. Повторные строки и повторная загрузка не удваиваются. Загрузка дополняет данные. Все старше шести календарных месяцев удаляются тем же обслуживанием, что и история бронирования. Пустой/неверный файл не создаёт фиктивный день с данными.

Для рейса берётся определённый по GPS автобус; при отсутствии GPS допустим однозначный госномер из привязки расписания/водителя. Автобус по одним отметкам СКУД не угадывается. Окно по ПЛАНОВОМУ времени: [отправление − 30 минут, отправление + 30 минут], обе границы включены. Например, 09:00 → 08:30:00–09:30:00. Повторные отметки карты на одном рейсе дают одного пассажира. Один и тот же проезд не назначается нескольким пересекающимся рейсам; спорные карты показываются отдельным количеством, свободные места по спорному факту не рассчитываются. Сопоставление выполняется до фильтра направления и даты, учитывает соседний день и переход через полночь.

«Факт по СКУД» отражает уникальные карты в загруженных данных. Для полного результата загружается полная выгрузка за день; частичный файл содержит лишь имеющиеся в нём отметки. При отсутствии выгрузки или однозначного автобуса — прочерк. Ноль означает, что для определённого автобуса на загруженную дату в окне нет отметок. Для ещё не открывшегося окна будущего рейса факт не показывается. Открытое/неполное окно и неоднозначность обозначаются звёздочкой; свободные места остаются неизвестными. Отметки из будущего относительно времени формирования отчёта не учитываются.

Показатели считаются независимо: «Свободно мест по броням» = max(0, вместимость − действующие брони); «Свободно мест по СКУД» = max(0, вместимость − уникальные карты). Факт не обрезается по вместимости. Число бронирований и отметок водителя остаётся отдельным. СКУД не меняет GPS-статус выполнения рейса. Сводные значения СКУД относятся к рейсам с данными, их количество указано рядом с показателем.

Публичная аналитика и Excel содержат только агрегаты СКУД; номера карт, идентификаторы сотрудников и исходные строки не публикуются. В детализации, итогах даты/направления и сводке добавлены оба новых показателя. В Excel на листе «Рейсы» новые столбцы добавлены после прежних 21: V — факт СКУД, W — свободно по СКУД, X — статус, Y — спорные карты. GPS-столбцы и их типы сохранены. Старые базы без таблиц СКУД читаются как «Нет выгрузки».

Перед публикацией: init_schema добавляет три новые таблицы и индексы, не меняя существующие записи. В booking-приложение нужно установить scud.py, admin-scud.js/.css и app.py (модуль и assets прежде app.py), затем перезапустить booking, чтобы создать таблицы. Аналитика переключается на тот же снимок и перезапускается. Нужны согласованное окно и согласованная SQLite-копия для страховки. Откат восстанавливает только код/ссылку и два сервиса; аддитивные таблицы сохраняются, база с новыми бронями не откатывается. Nginx, systemd и firewall не меняются.

Проверки: tests/test_scud.py (20 тестов: приватность, дедупликация, нормализация, границы, полночь, неоднозначность, независимые места, read-only/Excel); tests/scud_browser.py/js (реальные HTTP и Chromium, защищённый импорт в пропусках, несколько файлов, повтор, ошибки/лимиты/CSRF, RU/TR, мобильный вид и публичные агрегаты).
