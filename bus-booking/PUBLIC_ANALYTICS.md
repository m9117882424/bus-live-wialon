# Публичная аналитика бронирования

Отдельный сервис и страница /analytics/ без авторизации. Основное приложение бронирования не импортируется и не перезапускается. База бронирования открывается через SQLite mode=ro и PRAGMA query_only; миграций и записей в неё нет. Кэш выездов хранится отдельно. В публичном JSON и XLSX нет пропусков, имён пассажиров, кодов броней, токенов, координат или аккаунтов администратора.

## Данные и интерфейс

Девять плашек, период до 31 дня, фильтр направления, графики по дням, раскрытие дата → направление → рейс и итоговая сводка. Брони и подтверждённые посадки показаны двумя соседними столбцами. Бронь туда и обратно учитывается как два места на двух рейсах. Отменённые брони исключаются. Неотмеченная посадка не означает доказанную неявку. Предстоящие рейсы не попадают в количество выездов без GPS.

Расписание учитывает сроки действия, конкретную дату и дни недели. Заполненные исторические рейсы восстанавливаются из сохранённых данных бронирования, включая выключенные/удалённые маршруты. Пустые исторические рейсы рассчитываются по текущему расписанию: приложение ранее не сохраняло историю его изменений. В отчёте это явно указано.

Кнопка «Выгрузить в Excel» использует те же применённые фильтры и создаёт XLSX: «Сводка», «По датам», «Рейсы», «Правила». Счётчики и минуты — числа; даты и времена — значения Excel. Есть фильтры, закрепление строк и группировка дат. Строки, начинающиеся как формулы Excel, экранируются.

## Wialon

Повторно используется существующий модуль /opt/bdd-bus-report/current/geo_api.py: WialonClient, выгрузка истории с пагинацией, каталог объектов, Zone.contains. Существующий сервис и его сессия не меняются. Каждый запрос истории имеет отдельную сессию и курсор. Секрет доступен только через systemd LoadCredential.

Привязки проверены на реальном каталоге 17.11.2026:

| Направление | Ресурс | Геозона | Название |
| --- | --- | --- | --- |
| В ШОКмаркет | 600894911 | 30 | İspanyol kamp / Испанский камп |
| В Камп | 601276657 | 12 | Шок маркет Бюкеджели |

Используется именно магазин в Бюкеджели, не SOK MARKET Tasucu. Автобусы берутся из номеров аккаунтов водителей; назначение рейса подтверждается автобусом в отметках посадки или госномером в комментарии расписания. Без назначения принимается только однозначный ближайший по времени выход автобуса из геозоны отправления. Приоритет имеет автобус, привязанный к конкретному рейсу. Прибытие в пункт назначения не требуется для фиксации выезда. Параллельные рейсы и несколько кандидатов остаются неоднозначными; минуты не выдумываются.

Выход подтверждается двумя GPS-точками вне зоны после пребывания внутри; минимальное подтверждение 20 секунд. Пропуски GPS более 180 секунд разрывают наблюдение. Время — первая подтверждённая внешняя точка, без интерполяции. Окно сопоставления ±45 минут; разница = факт − расписание, округление до 0,1 минуты. Повторное использование одного выхода исключено, включая соседние календарные дни. Рейс вне выбранного дня тоже учитывается при разрешении пограничных совпадений. Отсутствие данных, ошибки загрузки и неоднозначность не считаются выездом вовремя.

История собирается последовательно в фоне. Страница не ждёт сетевых запросов Wialon. Кэш обновляется каждые 5 минут для сегодня/вчера, раз в 6 часов для старых дней; временная ошибка повторяется не раньше минуты. Очередь ограничена 256 заданиями. Периоды без рейсов не создают запросы истории.

## Запуск и публикация

Зависимости: requirements-analytics.txt. Установить отдельно в /opt/bus-public-analytics/venv. Снимок репозитория размещать в /opt/bus-public-analytics/releases/<git-sha>, ссылка current указывает на этот снимок.

Шаблон systemd: deploy/bus-public-analytics.service. Шаблон Nginx: deploy/nginx-public-analytics.locations.conf. Процесс слушает только 127.0.0.1:18346. DynamicUser, ProtectSystem, ReadOnlyPaths и отдельный StateDirectory ограничивают запись собственным кэшем. Не копировать в сервис пароли администратора или весь .env приложения бронирования.

Перед публикацией: изолированные тесты, проверка XLSX и браузера, CI, затем старт нового сервиса и loopback health/report/export. После согласованного окна добавить location в TLS server, выполнить nginx -t и плавный reload Nginx. Перезапуск бронирования не требуется. При откате удалить только новый location, проверить и reload; остановить только новый сервис. К базе бронирования откат не применяется, она не менялась.

Проверки:

    python tests/test_public_analytics.py
    node --check public_analytics/static/analytics.js

Реальный браузерный сценарий tests/public_analytics_browser.js запускается с URL изолированного сервера на синтетической БД. Дополнительно проверяются текущие правила бронирования и учётные записи водителей.
